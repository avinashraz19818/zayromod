# Independent backend and data

MizanMods runs its own Express process and stores build metadata in `DATA_DIR/mizanmods.sqlite`. The database is created automatically with a `builds` table (UUID, JSON configuration, status, progress, timestamps, bounded log, SHA-256, byte count) and a created-time index. WAL mode and busy timeout are enabled. There is no seed admin account, imported database, shared session table or external storage bucket.

Authentication is a new installation-specific bearer token, minimum 32 characters. It must be generated by the deployment owner and protected with TLS. All build/status/download/environment routes require it; only static UI and a minimal liveness endpoint are public. API bodies are limited, configuration is validated, and rate limits are enabled. Build tokens are never placed in URLs, assets or browser persistent storage.

## Firebase decision

Firebase is **not required or configured** in this implementation. No Firebase SDK, REST bridge, project ID, API key, service account, cloud collection, storage rule or existing account is included. The generated app is offline-only and never calls the build API.

A new Firebase project has **not been provisioned**. The user's requested cloud Firebase setup is therefore not delivered. If the client needs Firebase later:

1. Create a new client-owned cloud project in their account with appropriate billing/region choices.
2. Define cloud authentication/roles and database/storage needs before adding SDKs.
3. Use a workload identity or private secret-manager credential; do not commit a service-account file.
4. Start with deny-by-default Firestore/Storage rules and validate them in emulators.
5. Implement and test explicit MizanMods-only APIs/migrations. Never add a fallback to an existing application's project, URL or key.

This is a future integration checklist, not a claim of a verified Firebase connection. Current verified isolation is the independent local SQLite backend.
